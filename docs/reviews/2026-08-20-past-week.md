# Past-week review (`53a660d..HEAD`, 25 commits) — 2026-08-20

Multi-agent review of the week's work — the query API phases 2–3, the
pose-arbitration tri-state, cache hardening. 8 finder angles → ~30
candidates → 21 verified by four adversarial verifiers: 15 CONFIRMED
(several reproduced by executing production code against real fixtures),
2 PLAUSIBLE, 1 REFUTED. Every `(review, 2026-08-20)` citation in the code
resolves here. All findings below were **fixed the same session**, with
tests; the fix notes name the change.

The dominant theme: the `arbitrated` tri-state was sound as a *cross-run*
cache contract but was never checked against the *same-run* driver
(W1–W3), and the API's reload/warmup state machine had three coherence
holes (W4, W9, W10).

## Correctness (fixed, most severe first)

- **W1** `src/poser.py:283` / `src/cache_checker.py` — recording
  `arbitrated=False` mid-run made the just-written pose fail
  `pose_is_sufficient` on the driver's re-route, so every rate-limited /
  cancelled / twice-unparseable arbiter call became an unbounded same-run
  re-render/re-escalate/re-bill loop; each lap bumped `last_progress`, so
  the stall watchdog never fired. Verified end-to-end by executing `route`
  against an `{arbitrated: false}` entry. **Fix:** `route(..., settled=)`;
  the driver's `Resolved` arm passes `settled=True` and skips the
  sufficiency re-check — `false` now means "ask again on a later run" and
  only that.
- **W2** `src/pose.py:693` — only urllib HTTPError 429/503 became
  `RateLimited`; socket timeouts, URLError, HTTP 5xx and every
  claude-backend failure took the generic branch and were recorded
  permanently non-retryable (key absent). **Fix:** `VLMUnavailable`
  (transient superclass, `RateLimited` subclasses it): network-layer
  failures and other 5xx map to it in `_ask_gemini`; `_ask_claude` raises
  it for timeouts, non-zero exits and a missing binary; `_fold` catches the
  base and records `arbitrated=False`.
- **W3** `src/poser.py:233` — `settle`'s abandoned-on-timeout path recorded
  nothing, so calls in flight at Ctrl-C left `arbitrated` absent — the
  permanent-pin hole the CancelledError branch had closed for queued calls.
  **Fix:** `record_pose(..., arbitrated=False)` beside `abandoned += 1`.
- **W4** `src/api.py:362` — `post_reload` cleared `state.load_error`
  unconditionally while reloading only the Collection: a failed SigLIP load
  was erased and could never be retried (`warm` is one-shot), leaving
  `/status` at `ready: false, failure: null` forever. Reproduced against
  the real fixture. **Fix:** `warm` stashes `load_embed`; `/reload` retries
  it when the embed is missing (non-blocking `embed_loading` lock, so two
  loaders never double the VRAM) and clears `load_error` only when the
  server is actually ready.
- **W5** `src/collection.py:225` — `cache_root`'s unguarded `json.loads` of
  run-params.json ran *before* the CacheUnusable try, and a list/null-shaped
  pose-cache.json raised AttributeError the except clause didn't name; both
  escaped `POST /reload` as bare 500s. Reproduced. **Fix:** the whole load
  preamble moved inside the boundary; `load_pose_cache` validates shape
  (non-dict top level → ValueError, non-dict entries dropped like stale).
- **W6** `src/collection.py:374` — `entry_up` accepted a zero or NaN up
  (json.loads accepts a bare `NaN`), and `rotation_to_z_up` then raised out
  of `pose_of` — one hand-edited entry 500ed a whole /query response.
  Reproduced. **Fix:** finite/non-zero check in `entry_up`, the declared
  single validator.
- **W7** `src/pose.py:769` — the claude backend saved every arbiter
  thread's contact sheet to one fixed `scratch_dir/pose-sheet.png` and
  handed the path to a subprocess: concurrent workers could arbitrate one
  model against another's sheet and silently write a wrong up as
  `source: vlm`. Pre-existing (blame `19a3b6e1`) but the diff rewrote the
  enclosing loop. **Fix:** mkstemp per call, unlinked in a finally.
- **W8** `src/cachedir.py:157,272` — the "atomic" walk-cache and stamp
  writes used a fixed `.tmp` shared by every writer, so the concurrent
  classify-run/`/reload {"rescan": true}` case the comment cites could
  still publish a torn file (and the loser's replace raised
  FileNotFoundError); neither site unlinked its tmp on ENOSPC. Reproduced.
  **Fix:** `cachedir.write_atomic` (mkstemp + finally-unlink + chmod 644),
  used by the walk cache, the stamp and `Done.flush`.
- **W9** `src/api.py:109` — `warm()` assigned `state.collection`
  unconditionally, so a successful `/reload` landing during warmup (a real
  window: 2801 np.load calls on embed-cache2) was silently reverted to the
  pre-rescan collection when the warm thread finished. **Fix:** a
  generation counter; warm binds only if its generation still stands.
  Writers share `state.bind`; readers stay lock-free under the bind-once
  rule. (The counter originally bumped only on success, which left the
  `load_error` half of the same race open — closed as W11, 2026-08-21.)
- **W10** `src/api.py:360` — a failed `/reload` on a healthy server
  answered `503 {"ready": true}` — a self-contradiction surface.md's
  consumer folded into its warming policy while `/query` served 200s.
  **Fix:** 409 `{reloaded: false, ready: true, failure}` on a serving
  process; the 503 `_unready` envelope only when the server truly is not
  ready. surface.md §`POST /reload` updated.

## Follow-up — 2026-08-21 (reproduced by Masa)

- **W11** (same class as W4/W9) `src/api.py` — warm's tail cleared
  `load_error` unconditionally: the generation guard covered the collection
  bind but not the error, and a *failed* `/reload` never bumped the counter,
  so a reload failing during the warmup window had its recorded failure
  erased when warm finished — with a `VolumeUnavailable` erased, `/status`
  went back to `present: true, failure: null` while the drive was gone.
  **Fix:** `supersede_warm()` is called by every state-writing reload,
  failure branch included, and warm's tail *and* except arm are
  generation-guarded (the except arm is the mirror: a late warm failure must
  not mark a healthy post-reload server broken). Deliberate consequence,
  documented in `warm`'s docstring: a collection warm loaded while a reload
  failed is discarded — the reload's read is the more recent finding, and
  the operator's retry is the recovery.
- `save_run_params` was still a bare `write_text` after W8 introduced
  `write_atomic` — and W5's own test tears run-params.json to prove a torn
  manifest is reachable. Moved onto the helper.
- `write_atomic`'s chmod hardcoded 0644, which silently widened files under
  a 077 umask; it now applies 0666 under the process umask (read once at
  import, before threads exist), asserted against a `write_text` oracle.
- The unscoped-matrix shortcut got its identity test
  (`seen[0] is c.matrix`), and the embed-retry block moved into
  `ServerState.retry_embed()` so the handler stops reaching into
  underscored state.
- The 409 contract change was communicated to model-browser explicitly
  rather than left for them to discover. Their session checked their own
  code and reported back (2026-08-21): model-browser never calls `/reload`
  — its only contact with this API is `GET /status` (the probe in
  `server/src/semantic.ts`, branching on `ready`/`volume.present`) and the
  query endpoints, where the unchanged 503 `{ready, elapsed}` envelope is
  the only status it branches on. No consumer change needed.
